# 小红书账号状态与违规取证

用户报「笔记违规 / 被限流 / 收到警告」时，先取证再下结论，别凭猜测改文案或删笔记。

## 1. 创作中心笔记管理（首选，可自动化）

- 直达：`https://creator.xiaohongshu.com/new/note-manager`
- 旧路由（`/creator/note`、`/creator/notify`）会 302 到 `/new/home`，页面文本里根本没有笔记列表 → 别据此判定「无违规」。
- 路由不稳时的可靠入口：打开 `https://creator.xiaohongshu.com/new/home`，用 `get_by_text("笔记管理", exact=True).first.click()` 进入。
- 三个状态标签：`全部 N` / `已发布` / `审核中` / `未通过`；点标签后 dump body 文本即可。
  - `未通过` 有内容 → 平台侧违规判定成立，点进该条看原因与申诉入口。
  - `未通过`、`审核中` 都为空且全部在 `已发布` → 平台后台没有笔记级违规记录，警告来自 APP 站内信或账号级风控，**要用户截图**。
- 列表每项的曝光/点赞数字可用来判断是否被整体限流（新号个位数曝光正常，不足以单独说明限流）。

## 2. 主站站内信（常读不到）

- `https://www.xiaohongshu.com/notification`、`/messages` 需要主站登录态；服务器出口 IP 被标记时整站返回 `IP at risk. Switch to a secure network and retry. 300012`，redirect 到 `/website-login/error`。
- 这是**服务器 IP 层面的风控**，不是 cookie 失效：创作中心仍可进，主站全挂。此时不要反复重试刷页面（只会加重 IP 画像），直接告诉用户「后台无违规记录、主站被 IP 风控挡住」，请其截图 APP 通知。
- IP 风控本身也是发布风险的信号：同 IP 高频发布同类内容更容易触发账号级警告。

## 3. 探针骨架（patchright + 已存 cookie）

```python
from patchright.async_api import async_playwright
b = await p.chromium.launch(headless=True,
    executable_path="/home/ubuntu/.cache/ms-playwright/chromium-1234/chrome-linux64/chrome")
ctx = await b.new_context(storage_state="cookies/xiaohongshu_<账号>.json")
```

- 用 sau 的 `.venv/bin/python` 跑，并清掉 `PYTHONPATH`（否则 `utils` 包冲突）。
- 一次探针只开 2-3 个页面、间隔数秒，别循环刷新。
- 关键词扫描 `违规 / 限流 / 申诉 / 仅自己可见 / 审核` 比读整页文本更快定位。

## 4. 判定与动作

| 取证结果 | 结论 | 动作 |
|---|---|---|
| `未通过` 有条目 | 笔记级违规 | 读原因→按条款改文案/换素材→申诉或重发 |
| 全部 `已发布`，主站可读 | 警告在站内信 | 读信定位条款再决定 |
| 全部 `已发布`，主站 IP 风控 | 账号/网络级风险 | 暂停发布，请用户截图，评估换出口 IP |
| 曝光长期个位数 + 新号 | 正常冷启动 | 不据此判定限流 |
| 发布接口返回 `result:-9136 因违反社区规范禁止发笔记` | 账号级禁发 | 停发；APP 端申诉/联系客服；删除违规笔记**不解除**账号禁发，需等处罚期或申诉通过 |

> 判断「发布按钮点没点中」vs「点了但被平台拒绝」：挂 `pg.on("request")` + `pg.on("response")` 过滤 `note|publish|sns` URL。零请求 = 没点中真实按钮（重新定位）；有 POST `/web_api/sns/v2/note` 且响应 `-9136` = 账号禁发（别再重试）。

## 4.5 违规通知的处理路径（重要）

- **网页端无法编辑已发布笔记**：创作中心点笔记卡片没有「编辑」按钮（0 个匹配），发布页也不支持已发内容回编。补 AI 声明 / 申诉 / 删除都只能在**小红书 APP** 端做：`我 → 笔记 → 目标笔记 → ··· → 编辑`（找「内容声明」选「笔记含AI合成内容」），或用通知里的「我要申诉 / 删除笔记」。
- 用户截图违规通知后，若平台建议「为 AI 生成内容补充 'AI生成' 属性标注」→ 直接引导 APP 端编辑补标注，或删掉旧条重发（重发会自动带「笔记含AI合成内容」声明，合规）。
- 别在网页端反复试探编辑入口（无此功能），也别替用户点「删除笔记」——删除是不可逆的，先问用户。

## 5. 常见触发原因（经验排序，非平台结论）

1. 音乐版权：用知名歌曲原曲/AI 翻唱做 MV，最易被判侵权或搬运。
2. 声明错位：sau 旧代码自动点「来源转载已声明」，自制 AI 内容被标成「转载」→ 被判『包含利用AI创作但未声明的内容』。已修：declare_ai_content 提升到基类，视频/图文路径统一声明「笔记含AI合成内容」；发布日志看到 `已声明：笔记含AI合成内容` 才算合规。
3. AI 生成内容未按平台要求标注。
4. 同 IP 高频发布（服务器 IP 被风控时尤甚）。
