# AI 直出带文字图流水线（2026-09-08 用户规范·新流程）

## 提示词格式（硬性规范）
```
[画面风格]
{用户给的风格段，原样保留，中英文跟随不翻译}
[画面内容]
{文章中文内容，直接贴}
```
- ❌ 不写英文画面意象（`A vintage detective bureau: ...`）
- ❌ 不加 `no text, no letters, no words`（那会让 AI 不渲染文字）
- ❌ 不 PIL 叠字（旧流程已废弃）

## 内容规范
- 每篇 5-10 张图，把一项学习技能说透（封面 + 机制/案例/方法/总结）
- 每张 200-400 字（AI 直出清晰渲染上限；超 500 糊）
- 文章内容全放图里 → 小红书正文只留引导语+标签（不再受 800 字限制）

## 脚本结构（参考 ~/tools/runhub/避坑续集/make_cards.py 与 ~/tools/runhub/升级三篇/make_cards.py）
- `STYLE` 常量 = 用户风格原样（勿改动措辞）
- `SERIES` dict：每套 = 一篇的 10 张；卡片元组 `(文件名, 中文内容)`
- 多套批量顺序跑（避免 RunningHub 队列互撞）；`if final_p.exists(): 跳过` 支持断点续跑
- prompt 拼法：`f"[画面风格]\n{STYLE}\n[画面内容]\n{text}"`
- 参数：ratio="3:4" res="2k"；t2i 直出保存（无 overlay）

## 流程（含两道确认门）
1. 扩写每张卡内容（200-400 字/张，10 张/篇）
2. **统计字量**：import make_cards 打印每张 len(text)，不达标先扩（本会话返工两次：平均 143→165→达标才跑）
3. **确认门①**：把第 1 张完整提示词发给用户过目（用户常在此改风格/字量/内容）
4. **确认门②**：生成 1 张样图 → 视觉模型不支持看图就直接 MEDIA 发用户确认渲染质量+风格
5. 全量后台生成（notify 完成）
6. 若是替换重发：先删旧版 → 逐篇 upload-note → verify_notes.py 验证

## 踩坑清单
- 改风格必须 `rm -f <目录>/*.png`（含 _base）再重跑，否则"跳过已存在"保留旧风格成品
- 用户中途改要求：先 kill 后台生成进程再改脚本（本会话两次 kill 都省了额度）
- RunningHub 查询 API 抖动返回非 dict → runhub_img.py poll() 已加容错（查询异常打印+重试继续）；若整批中断先确认容错还在
- 421 TASK_QUEUE_MAXED：脚本带 20-30s 重试
- 小红书标题渲染可能截断（如 `我这个 AI，怎么指挥 12 个 AI 同事干活` 显示为 `我这个 AI，怎么指挥 12 个 AI`）→ 删除匹配用短关键词
- 删除确认按钮顺序：`确定` → `.ant-btn-primary` → `确认`（patchright 同步 API，勿用 async/await）

## 2026-09-08 升级替换案例（3 篇旧流程→新样式）
- 脚本：`~/tools/runhub/升级三篇/make_cards.py`（3 套×10 张顺序跑）
- 执行：30 张生成（约 60 分钟）→ `delete_old_notes.py` 删旧版 3 篇（关键词：`AI 一周进化了多少` / `AI 学会了甄别` / `怎么指挥 12 个 AI`——第三个因含"同事干活"匹配 0 条，改成短关键词后成功）→ 逐篇发新版 → verify
- 发布命令每篇 10 张图；正文用引导语模板（`全部内容都在图里，放大看 👆` + tags）
