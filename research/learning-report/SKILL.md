# 学习汇报固定格式（四问）

## When to Use
- 学完一段内容（视频/文章/开源项目/工具介绍）后向用户汇报
- 用户分享外部内容要求验证后讨论

## 硬性格式（用户 2026-09-19 定，每次必答四问）
1. **这是什么东西** —— 一句话说清本质（是什么项目/工具/技术，真实星级）
2. **用来做什么的** —— 核心能力/场景，用表格列关键点
3. **对我做事有什么好处** —— 对用户业务/变现的实际价值，结合用户现有技能资产
4. **对你进化有什么好处** —— 对 Agent 能力/资产的价值

## 流程
1. **先验证再汇报**：不先入为主。GitHub 搜仓库（star/许可/更新日期）、拉 README 核验描述中的关键数字（如"99% 完成率""$1/条"），逐条对照用户转述
2. **标注可信度**：属实 ✅ / 有差距 ⚠️ / 查无实据 ❌，分别说明依据
3. **按四问结构输出**：验证结果并入第 1 问（是什么/真实度），后三问按用户视角写

## 判定归属
- 与已有技能/资产重合 → 说明"已掌握"，指出对应技能，不重复沉淀
- 将来有用但条件未满足（缺设备/key/接口）→ 建议记入待激活资产清单（~/项目目录/待激活资产.md），并写进度文件（~/项目目录/projects/<任务>/进度.md）供挂起续做
- 用户说"砍掉"时按支撑矩阵执行，存量不可逆资产保留不删

## 坑
- 数字转述要原文核验（README 原文 vs 宣传口径，如"官方称"与"第三方实测"要分开标）
- 工具/模型类内容优先查 GitHub API（api.github.com/search/repositories），raw.githubusercontent 在腾讯云常超时，改用 web_extract 或镜像
